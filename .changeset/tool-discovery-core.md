Add tool discovery. With `toolDiscovery` set on `generate` / `stream`, core-ai declares a discovery tool; the model's calls to it arrive as `ToolDiscoveryCall`s in the new `result.discoveryCalls` (never in `toolCalls`; in `parts` as `ToolDiscoveryCallPart`s wrapping them, streamed as one `tool-discovery-call` event), and the application answers each with a `ToolDiscoveryResultMessage` (`discoveryCallId`) listing `ToolSnapshot`s (tool definitions with plain JSON Schema parameters). Discovered tools are then callable by their real names on every provider and stay declared while their results are in the history. `finishReason: 'tool-calls'` covers pending discovery calls, so loop on `finishReason` and answer both `toolCalls` and `discoveryCalls`. Discovery calls pair with their results per step. Malformed discovery histories, reserved tool names, and a `toolChoice` naming a non-caller tool throw `ValidationError` before any provider call. A strict snapshot is declared without `strict` on models without strict tool support or beyond their `maxStrictTools` limit, so it never blocks a later request. `generateObject` and `streamObject` declare no discovered tools.

**Type change:** `ModelCapabilities` gains a required `tools.toolDiscovery` field (`'native' | 'emulated'`) and `GenerateResult` a required `discoveryCalls` array, so code that builds either by hand must add them. `Message` and `AssistantContentPart` gain the new members, so exhaustive switches over them must handle them. Adds adapter helpers (`resolveToolDiscovery`, `getEmulatedToolSet`, `emulateToolDiscoveryMessages`, and others); `finalizeGenerateResult` and the `request` option of `createChatStream` turn calls to the discovery tool into discovery calls.
