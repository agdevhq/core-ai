## Overview

The Anthropic provider gives you access to Claude models with advanced reasoning capabilities through adaptive and manual thinking modes.

## Installation

```bash
npm install @core-ai/anthropic
```

## createAnthropic()

Create an Anthropic provider instance.

```typescript
import { createAnthropic } from '@core-ai/anthropic';

const anthropic = createAnthropic({
    apiKey: process.env.ANTHROPIC_API_KEY,
});
```

### Options

<ParamField path="apiKey" type="string" optional>
    Your Anthropic API key. Defaults to `ANTHROPIC_API_KEY` environment
    variable.
</ParamField>

<ParamField path="baseURL" type="string" optional>
    Custom base URL for API requests.
</ParamField>

<ParamField path="defaultMaxTokens" type="number" optional>
    Default output limit for requests that omit `maxTokens`. When unset, each
    request uses the model's output ceiling. See [Output
    limits](#output-limits).
</ParamField>

<ParamField path="client" type="AnthropicChatClient" optional>
    Provide your own configured Anthropic client instance.
</ParamField>

### Returns

`AnthropicProvider` with method `chatModel()`.

## Model capabilities

Use `ChatModel.capabilities` to inspect the constraints for the selected model,
or call `getAnthropicModelCapabilities(modelId)` without creating a model:

```typescript
import {
    createAnthropic,
    getAnthropicModelCapabilities,
} from '@core-ai/anthropic';

const anthropic = createAnthropic();
const model = anthropic.chatModel('claude-opus-5');
const capabilities = model.capabilities;

const otherCapabilities = getAnthropicModelCapabilities('claude-opus-4-5');
```

For registered Claude models:

- `supportedEfforts` lists the accepted effort levels. Models with adaptive
  thinking may also support `max`.
- `mode` is `always-on` for `claude-opus-5-5`, `claude-fable-5-1`, and
  `claude-mythos-5-1`, because adaptive thinking cannot be disabled. For every
  other registered Claude model, `mode` is `optional` and reasoning is enabled
  by passing `reasoning`.
- `restrictsSamplingParams` is `true`. The exact temperature, `topP`, and
  `topK` rules are described under
  [Reasoning restrictions](/api/providers/anthropic#reasoning-restrictions).
- `supportedToolChoices` is `['auto', 'none']` while reasoning is enabled. On
  `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-fable-5-1`, and
  `claude-mythos-5-1` that restriction applies to every request, including
  requests that omit `reasoning`.
- `modalities.input` is `['text', 'image', 'file']` for every Claude model.
  Image sources accept both `base64` and `url`. File parts are PDF-only.
  `modalities.output` is `['text']`.
- `tools.strictSchemas` reports whether the model supports strict tool schemas.
  Supported models report `{ supported: true, maxStrictTools: 20 }`.
- `messages.systemPlacement` is `'before-reply'` from Claude Opus 4.8,
  Sonnet 5, and Haiku 5.5 on, and `'leading'` for earlier models. See
  [System messages](/api/providers/anthropic#system-messages).

### Strict tool schemas

Claude 4.5 and later models support per-tool `strict: true` and report
`{ supported: true, maxStrictTools: 20 }`. The 20-tool limit counts only tools
that set `strict: true`; exceeding it throws
[`ToolSchemaStrictnessError`](/api/core/errors#toolschemastrictnesserror)
locally. The limit is enforced by the Anthropic API (which rejects larger
requests with "The maximum number of strict tools supported is 20") but is not
listed on Anthropic's documentation pages.
Older models — Claude Opus 4.1, Opus 4, Sonnet 4, Sonnet 3.7, and Claude 3.x —
report `{ supported: false }` and reject explicit `strict: true` locally.
Unrecognized model IDs resolve optimistically to supported, so future Claude
models work without a registry update.

Only strict tools and structured-output schemas go through Anthropic's schema
normalization (`$schema` stripped, `additionalProperties: false` added,
numeric and length constraints removed, `oneOf` rewritten to `anyOf`).
Non-strict tools are sent with their raw JSON Schema, so declared constraints
reach the model as hints. Strict tool schemas do not change Anthropic's
structured response format for `generateObject()` and `streamObject()`. See
[Strict tool schemas](/guides/tool-calling#strict-tool-schemas) for the schema
contract, error reasons, and cross-provider behavior.

### System messages

Leading system messages become text blocks in Anthropic's top-level `system`
field. Models that report `'before-reply'` also accept a system message later
in the conversation, sent in place as a `role: 'system'` message. It must
directly follow a user or tool message and be the last message or be followed
by an assistant message:

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-sonnet-5-5'),
    messages: [
        { role: 'system', content: 'You are a support agent.' },
        { role: 'user', content: 'I want a refund.' },
        { role: 'system', content: 'Offer a manager callback.' },
    ],
});
```

A later system message keeps the cached conversation prefix intact, unlike a
change to the leading system messages. Claude Opus 4.7, Opus 4.6, Sonnet 4.6,
Opus 4.5, Sonnet 4.5, Haiku 4.5, and older models report `'leading'` and
reject later system messages with
[`UnsupportedSystemMessagePlacementError`](/api/core/errors#unsupportedsystemmessageplacementerror).
Unrecognized model IDs resolve to `'before-reply'`.

## Examples

### Basic chat

```typescript
import { createAnthropic } from '@core-ai/anthropic';
import { generate } from '@core-ai/core-ai';

const anthropic = createAnthropic();

const result = await generate({
    model: anthropic.chatModel('claude-sonnet-4-6'),
    messages: [{ role: 'user', content: 'Explain the theory of relativity' }],
});

console.log(result.content);
```

### Extended thinking

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-opus-5'),
    messages: [
        {
            role: 'user',
            content: 'Analyze this complex dataset and provide insights...',
        },
    ],
    reasoning: {
        effort: 'max',
    },
});

if (result.reasoning) {
    console.log('Reasoning:', result.reasoning);
}
console.log('Answer:', result.content);
```

The provider requests summarized thinking, matching the OpenAI provider's
reasoning-summary behavior. Every reasoning part also retains Anthropic's
signature so you can safely pass the result into a later tool-result request.

### Streaming

```typescript
import { stream } from '@core-ai/core-ai';

const chatStream = await stream({
    model: anthropic.chatModel('claude-sonnet-4-6'),
    messages: [{ role: 'user', content: 'Write a detailed analysis of...' }],
    reasoning: {
        effort: 'high',
    },
});

for await (const event of chatStream) {
    if (event.type === 'reasoning-delta') {
        process.stdout.write(event.text);
    } else if (event.type === 'text-delta') {
        process.stdout.write(event.text);
    }
}
```

### Tool calling

```typescript
import { generate, defineTool } from '@core-ai/core-ai';
import { z } from 'zod';

const result = await generate({
    model: anthropic.chatModel('claude-sonnet-4-6'),
    messages: [
        { role: 'user', content: 'What is the weather in San Francisco?' },
    ],
    tools: {
        getWeather: defineTool({
            name: 'getWeather',
            description: 'Get weather for a location',
            parameters: z.object({
                location: z.string(),
            }),
        }),
    },
});
```

### Vision and file inputs

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-sonnet-4-6'),
    messages: [
        {
            role: 'user',
            content: [
                { type: 'text', text: 'What is in this image?' },
                {
                    type: 'image',
                    source: {
                        type: 'url',
                        url: 'https://example.com/image.jpg',
                    },
                },
            ],
        },
    ],
});
```

<Note>
    Anthropic accepts image parts and PDF file parts. Other file MIME types are
    rejected.
</Note>

## Thinking modes

### Adaptive thinking

The model automatically determines thinking depth based on the effort level.

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-opus-5'),
    messages: [{ role: 'user', content: 'Complex problem...' }],
    reasoning: {
        effort: 'high',
    },
});
```

<Note>
    `claude-fable-5-1`, `claude-mythos-5-1`, `claude-fable-5`,
    `claude-mythos-5`, `claude-mythos-preview`, `claude-opus-5-5`,
    `claude-opus-5`, `claude-opus-4-8`, `claude-opus-4-7`, `claude-opus-4-6`,
    `claude-sonnet-5-5`, `claude-sonnet-5`, `claude-sonnet-4-6`, and
    `claude-haiku-5-5` support `'max'` effort directly. On `claude-opus-5-5`,
    `claude-fable-5-1`, and `claude-mythos-5-1`, thinking cannot be disabled.
    Omit `reasoning` to use the model's API default effort, or pass
    `reasoning.effort` to send adaptive thinking at that level.
    `claude-opus-5-5` and `claude-haiku-5-5` default to `medium`.
    `claude-sonnet-5-5`, `claude-fable-5-1`, and `claude-mythos-5-1` default to
    `high`.
</Note>

### Manual thinking budget (Claude 4.5 and earlier)

Manual-thinking models take a token budget instead of an effort level. This
library maps each effort to a budget. `high` and `max` are half and three
quarters of the model's output ceiling:

| Effort    | Budget                | Claude 4.5 (64,000 ceiling) | Opus 4 / 4.1 (32,000 ceiling) |
| --------- | --------------------- | --------------------------- | ----------------------------- |
| `minimal` | 1,024                 | 1,024                       | 1,024                         |
| `low`     | 2,048                 | 2,048                       | 2,048                         |
| `medium`  | 8,192                 | 8,192                       | 8,192                         |
| `high`    | 50% of output ceiling | 32,000                      | 16,000                        |
| `max`     | 75% of output ceiling | 48,000                      | 24,000                        |

The budget is spent out of `maxTokens`. If you set `maxTokens` (or
`defaultMaxTokens`) at or below the budget, the request throws a
`ValidationError`. The budget is never reduced to fit. Omit `maxTokens` to use
the model's output ceiling, which holds every budget.

`claude-opus-4-5` also accepts Anthropic's `effort` parameter alongside manual
thinking. To send it, pass it through `providerOptions`:

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-opus-4-5'),
    messages: [{ role: 'user', content: 'Complex reasoning task...' }],
    reasoning: { effort: 'high' },
    providerOptions: {
        anthropic: { outputConfig: { effort: 'medium' } },
    },
});
```

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-opus-4-5'),
    messages: [{ role: 'user', content: 'Complex reasoning task...' }],
    reasoning: {
        effort: 'high',
    },
});
```

## Output limits

`maxTokens` is the total output allowance: thinking and the visible answer
together. When you omit it, the request uses the first of:

1. `defaultMaxTokens`, if you set it on the provider
2. The model's output ceiling (`model.capabilities.output.maxTokens`)
3. 4,096, for model ids without a known ceiling

| Models                                                                                                                                                | Output ceiling |
| ----------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| Fable 5.1, Mythos 5.1, Fable 5, Mythos 5, Mythos Preview, Opus 5.5, Opus 5, Opus 4.8, Opus 4.7, Opus 4.6, Sonnet 5.5, Sonnet 5, Sonnet 4.6, Haiku 5.5 | 128,000        |
| Opus 4.5, Sonnet 4.5, Haiku 4.5, Sonnet 4, Sonnet 3.7                                                                                                 | 64,000         |
| Opus 4.1, Opus 4                                                                                                                                      | 32,000         |

Anthropic's output-token rate limits count only generated tokens, so a high
limit does not use up rate-limit capacity.

`generate()` and `generateObject()` stream from the Messages API internally
and return the same result as a non-streaming call. The Anthropic SDK requires
streaming for requests whose output limit could take longer than ten minutes,
which applies to these ceilings. A transient error that arrives mid-stream,
such as `overloaded_error`, surfaces as the matching core-ai error
(`ModelOverloadedError`) without an automatic SDK retry.

## Reasoning restrictions

When reasoning is enabled, Anthropic enforces additional request constraints:

- `temperature` must be omitted
- `topP` must be between `0.95` and `1`
- `toolChoice` must be `'auto'` or `'none'`
- `providerOptions.anthropic.topK` must be omitted

Claude Opus 5.5, Claude Sonnet 5.5, Claude Fable 5.1, Claude Mythos 5.1, Claude
Fable 5, Mythos 5, Mythos Preview, Opus 5, Opus 4.8, Opus 4.7, and Sonnet 5
also reject non-default sampling parameters when you do not explicitly enable
reasoning. For these models, use `temperature: 1`, `topP: 1`, and omit `topK`.

Claude Haiku 5.5 rejects non-default sampling parameters on every request. Set
`temperature` to `1` or `topP` to `0.99`, and omit `topK`. A request cannot
include both `temperature` and `topP`.

Claude Opus 5.5, Claude Sonnet 5.5, Claude Fable 5.1, and Claude Mythos 5.1
reject `toolChoice: 'required'` and `toolChoice: { type: 'tool', toolName }` on
every request. `'auto'` and `'none'` remain valid. Claude Fable 5, Claude
Mythos 5, and Claude Haiku 5.5 accept forced tool choice when `reasoning` is
omitted.

<Warning>
    Violating these constraints throws a `ValidationError` before the request is
    sent.
</Warning>

<Note>
    Adaptive thinking automatically supports reasoning between tool calls. For
    older compatible manual-thinking models, the adapter sends the
    `interleaved-thinking-2025-05-14` beta as an `anthropic-beta` header.
</Note>

### Reasoning metadata

When reasoning is enabled, Anthropic reasoning parts include provider metadata with signature and redacted data fields. Use `getProviderMetadata` to access them in a type-safe way.

```typescript
import { generate, getProviderMetadata } from '@core-ai/core-ai';
import type { AnthropicReasoningMetadata } from '@core-ai/anthropic';

const result = await generate({
    model: anthropic.chatModel('claude-opus-5'),
    messages: [{ role: 'user', content: 'Think step by step.' }],
    reasoning: { effort: 'high' },
});

for (const part of result.parts) {
    if (part.type !== 'reasoning') continue;

    const metadata = getProviderMetadata<AnthropicReasoningMetadata>(
        part.providerMetadata,
        'anthropic'
    );

    console.log(metadata?.signature);
    console.log(metadata?.redactedData);
}
```

The `AnthropicReasoningMetadata` type contains:

- `signature` -- cryptographic signature for multi-turn reasoning fidelity
- `redactedData` -- redacted thinking content, if present

## Provider-specific options

Options are namespaced under `anthropic` in `providerOptions`:

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-sonnet-5'),
    messages: [{ role: 'user', content: 'Hello' }],
    providerOptions: {
        anthropic: {
            stopSequences: ['\n\n'],
        },
    },
});
```

Available fields: `topK`, `stopSequences`, `betas`, `outputConfig`,
and `cacheControl`.

- `betas` are sent through the `anthropic-beta` request header.

System messages accept their own options under the same key. The only field is
`cacheControl`. See
[System message cache control](/api/providers/anthropic#system-message-cache-control).

## Prompt caching

Use `cacheControl` to enable Anthropic prompt caching. This maps to Anthropic's top-level `cache_control` request field and uses automatic caching for the reusable prompt prefix.

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-sonnet-4-6'),
    messages: [
        { role: 'system', content: 'You are a careful technical editor.' },
        {
            role: 'user',
            content: 'Summarize this document and keep all key dates.',
        },
    ],
    providerOptions: {
        anthropic: {
            cacheControl: { type: 'ephemeral' },
        },
    },
});

console.log(result.usage.inputTokenDetails.cacheReadTokens);
console.log(result.usage.inputTokenDetails.cacheWriteTokens);
```

You can request a 1-hour cache TTL when you expect follow-up requests to arrive later than Anthropic's default 5-minute cache window:

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-sonnet-4-6'),
    messages: [{ role: 'user', content: 'Summarize this large document.' }],
    providerOptions: {
        anthropic: {
            cacheControl: { type: 'ephemeral', ttl: '1h' },
        },
    },
});
```

### System message cache control

Set `cacheControl` on a system message to place an explicit cache breakpoint
at the end of that message. Each breakpoint can use its own TTL. A common setup
for agent loops caches the static system prompt for an hour and lets
request-level caching follow the growing conversation:

```typescript
const result = await generate({
    model: anthropic.chatModel('claude-sonnet-5-5'),
    messages: [
        {
            role: 'system',
            content: largeStaticInstructions,
            providerOptions: {
                anthropic: {
                    cacheControl: { type: 'ephemeral', ttl: '1h' },
                },
            },
        },
        ...conversation,
    ],
    providerOptions: {
        anthropic: {
            cacheControl: { type: 'ephemeral' },
        },
    },
});
```

Breakpoints follow Anthropic's limits, checked before the request:

- At most 4 breakpoints per request, request-level `cacheControl` included.
- A `1h` breakpoint cannot follow a `5m` one. System messages render in
  order, and request-level `cacheControl` comes last.
- When the conversation ends with a system message that sets `cacheControl`,
  request-level `cacheControl` must use the same TTL.

A request that breaks a limit throws `ValidationError`. A missing `ttl` means
`5m`.

Anthropic reports cache usage in `result.usage.inputTokenDetails`:

- `cacheReadTokens`: Tokens served from an existing cache entry
- `cacheWriteTokens`: Tokens written to the cache for future requests

Anthropic only caches prompts above the model's minimum cacheable length:

- 512 tokens for Claude Opus 5.5, Claude Sonnet 5.5, Claude Fable 5.1, and Claude Mythos 5.1
- 1024 tokens for Claude Opus 4.8
- 1024 tokens for Claude Sonnet 4.5, Claude Opus 4.1, Claude Opus 4, Claude Sonnet 4, and Claude Sonnet 3.7
- 2048 tokens for Claude Sonnet 4.6
- 4096 tokens for Claude Opus 4.6, Claude Opus 4.5, and Claude Haiku 4.5

## Error handling

```typescript
import { ProviderError } from '@core-ai/core-ai';

try {
    const result = await generate({
        model: anthropic.chatModel('claude-sonnet-4-6'),
        messages: [{ role: 'user', content: 'Hello!' }],
    });
} catch (error) {
    if (error instanceof ProviderError) {
        console.error('Anthropic API error:', error.message);
        console.error('Status:', error.statusCode);
    }
}
```
