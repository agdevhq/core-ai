title: Tool Calling
description: Let models use external tools and functions with defineTool()
---

Tool calling enables language models to interact with external functions and APIs, extending their capabilities beyond text generation.

## Define a Tool

Create tools using `defineTool()`. `parameters` takes a [Standard Schema](https://standardschema.dev) with JSON Schema support, such as a Zod 4.2+ schema, or plain JSON Schema. See [Schemas](/guides/structured-outputs#schemas) for the supported libraries.

```typescript
import { defineTool } from '@core-ai/core-ai';
import { z } from 'zod';

const weatherTool = defineTool({
    name: 'get_weather',
    description: 'Get mocked weather information for a city',
    parameters: z.object({
        location: z.string().describe('City name'),
        unit: z.enum(['celsius', 'fahrenheit']),
    }),
});
```

## Strict tool schemas

Set `strict: true` on a tool to make the provider enforce the tool's parameter
schema during argument generation. Strictness is a per-tool opt-in: omitting
`strict` or setting `strict: false` keeps that tool non-strict on every
provider.

```typescript
const lookupOrder = defineTool({
    name: 'lookup_order',
    description: 'Look up an order by id',
    strict: true,
    parameters: z.object({
        orderId: z.string(),
        note: z.string().nullable().describe('Extra note, or null'),
    }),
});
```

### Strict-capable schema contract

A strict tool's schema must fit the strict-capable subset that schema-enforcing
providers accept. Core-ai validates strict tools against this contract locally,
before any API call, and reports every violation with a fix hint. Non-strict
tools are never validated against it.

The contract applies to the tool's JSON Schema, so it covers Standard Schemas
and plain JSON Schema alike. The examples below use Zod; other libraries
produce the equivalent JSON Schema keywords.

- **Closed objects with every key required.** Use `.nullable()` for values the
  model may leave out — `.optional()` makes a key optional and is rejected, and
  `.default()` also makes a key optional.
- **Object root.** `parameters` must describe an object, such as a
  `z.object()`; a primitive, array, or union at the root is rejected.
- **Allowed keywords** — the intersection of what OpenAI and Anthropic accept
  in strict mode, not the union: `$ref` / `$defs`, `type` (`object`, `array`,
  `string`, `number`, `integer`, `boolean`, `null`), `properties`, `required`,
  `additionalProperties: false`, `items`, `enum`, `const`, unions (`anyOf`
  from `z.union()`, and `oneOf` from `z.discriminatedUnion()`, which providers
  receive as `anyOf`), `format` (`date-time`, `time`, `date`, `duration`,
  `email`, `hostname`, `ipv4`, `ipv6`, `uuid`), `pattern`, `title`,
  `description`, `default`, `examples`.
- **Rejected:** numeric bounds (`minimum`, `maximum`, `multipleOf` — Zod's
  implicit safe-integer bounds on `z.int()` are exempt and stripped), string
  and array length constraints (`minLength`, `maxLength`, `minItems`,
  `maxItems`), URL formats (`z.url()` emits `format: "uri"`, which OpenAI does
  not accept — use `z.string()`), intersections (`z.intersection()` / `.and()`
  emit `allOf` — flatten into one `z.object()`), tuples (`prefixItems`),
  `not`, open objects (`z.record()`, `.catchall()`, `.passthrough()`,
  `z.looseObject()`), and recursive schemas (`z.lazy()`).

Check constraints you remove from the schema (ranges, lengths) in your tool
implementation.

### Check model support

`model.capabilities.tools.strictSchemas` reports whether the selected model
supports strict tools and any provider limit:

```typescript
import { createOpenAI } from '@core-ai/openai';

const model = createOpenAI().chatModel('gpt-5-mini');
const strictSchemas = model.capabilities.tools.strictSchemas;

if (strictSchemas.supported) {
    console.log(strictSchemas.maxStrictTools); // provider limit, if any
}
```

Unknown and future model IDs resolve optimistically to `{ supported: true }`:
core-ai forwards the explicit `strict: true` and lets the provider reject the
request if the model genuinely lacks support. This keeps newly released
models usable without a registry update. Fine-tuned OpenAI `ft:<base>:...`
models inherit their base model's capabilities instead.

### Errors

Invalid strict configuration throws
[`ToolSchemaStrictnessError`](/api/core/errors#toolschemastrictnesserror)
before the provider request. Its `reason` is one of:

- `'unsupported'` — the model is known not to support strict tool schemas.
- `'limit-exceeded'` — the request contains more strict tools than the
  provider's `maxStrictTools` limit.
- `'invalid-schema'` — a strict tool's schema is outside the strict-capable
  contract. The error carries a `violations` array naming each offending
  schema path:

```text
openai model "gpt-5-mini" received strict tools whose schemas are outside the
strict-capable schema contract: tool "search" at properties.limit.maximum:
remove numeric bounds (.max()/.lt()/.lte()) — numeric range constraints are
outside the strict-capable subset; validate ranges after parsing instead
```

### Parallel tool calls

OpenAI does not guarantee schema adherence when parallel tool calls are
enabled. Core-ai does not change that setting for you: when you combine strict
tools with `providerOptions.openai.parallelToolCalls: true`, set it to `false`
yourself if you need guaranteed adherence.

### Provider support

| Provider                     | Strict tool schemas                                                                                                                                                    |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                    | Yes, on Claude 4.5 and later models; at most 20 strict tools per request                                                                                               |
| Anthropic Vertex             | Yes; requires the `structured_outputs` partner-model feature in your organization policy — see [Anthropic Vertex](/api/providers/anthropic-vertex#strict-tool-schemas) |
| OpenAI                       | Yes                                                                                                                                                                    |
| Azure OpenAI                 | Yes; classic deployments need `api-version` `2024-08-01-preview` or later                                                                                              |
| Kimi                         | Yes                                                                                                                                                                    |
| OpenAI Compat                | Yes, when the endpoint implements OpenAI strict function tools                                                                                                         |
| Omnifact                     | Yes                                                                                                                                                                    |
| Google GenAI / Google Vertex | No; `strict: true` throws locally                                                                                                                                      |
| Mistral                      | No; `strict: true` throws locally                                                                                                                                      |

On the OpenAI family (`openai`, `azure-openai`, `kimi`, `openai-compat`,
`omnifact`), strict tools are sent with `strict: true` and a normalized schema
(`$schema` stripped, `additionalProperties: false` added recursively, `oneOf`
rewritten to `anyOf` — all semantics-preserving). Non-strict tools are sent
with the tool's JSON Schema unchanged. On the Responses API they carry an explicit
`strict: false`, because that API otherwise tries to normalize tools into
strict mode on its own; on Chat Completions, which is non-strict by default,
the field is omitted. Anthropic follows the same split: strict tools get the
provider's normalization (which also drops the numeric and length constraints
its strict grammar rejects), non-strict tools are sent raw.

<Warning>
    Strict generation reduces invalid arguments but does not make tool execution
    trusted. Check `ToolCall.validation`, or validate `ToolCall.arguments`
    yourself for plain JSON Schema tools, before executing code or making
    external requests. See [Validate tool calls](#validate-tool-calls).
</Warning>

Strict tool schemas apply to function arguments during `generate()` and
`stream()`. They are separate from the structured response formats used by
[`generateObject()`](/api/core/generate-object) and
[`streamObject()`](/api/core/stream-object). A provider can support one without
supporting the other.

## Basic Tool Usage

Implement a complete tool calling flow:

```typescript
import { defineTool, generate, resultToMessage } from '@core-ai/core-ai';
import { createOpenAI } from '@core-ai/openai';
import { z } from 'zod';

const openai = createOpenAI({ apiKey: process.env.OPENAI_API_KEY });
const model = openai.chatModel('gpt-5-mini');

// Define the tool
const weatherParameters = z.object({
    location: z.string().describe('City name'),
    unit: z.enum(['celsius', 'fahrenheit']).default('celsius'),
});

const weatherTool = defineTool({
    name: 'get_weather',
    description: 'Get mocked weather information for a city',
    parameters: weatherParameters,
});

// Implement the tool function
function runWeatherTool(args: z.output<typeof weatherParameters>): string {
    const conditions = ['sunny', 'cloudy', 'windy'];
    const condition = conditions[args.location.length % conditions.length];
    const temperature = 10 + (args.location.length % 18);

    return JSON.stringify({
        location: args.location,
        unit: args.unit,
        temperature,
        condition,
    });
}

// Initial request with tools
const initialMessages = [
    {
        role: 'user' as const,
        content: 'What is the weather in Berlin? Reply in one sentence.',
    },
];

const firstResult = await generate({
    model,
    messages: initialMessages,
    tools: { get_weather: weatherTool },
    toolChoice: 'auto',
});

// Check if model wants to call tools
if (firstResult.finishReason !== 'tool-calls') {
    console.log('Model response without tool calls:', firstResult.content);
    process.exit(0);
}

// Execute the tool calls
const toolMessages = firstResult.toolCalls.map((call) => {
    if (call.name !== 'get_weather' || !call.validation) {
        return {
            role: 'tool' as const,
            toolCallId: call.id,
            content: JSON.stringify({ error: `Unknown tool: ${call.name}` }),
            isError: true,
        };
    }

    // core-ai validated the arguments against weatherParameters
    if (call.validation.issues) {
        return {
            role: 'tool' as const,
            toolCallId: call.id,
            content: JSON.stringify({
                error: 'Invalid arguments',
                issues: call.validation.issues,
            }),
            isError: true,
        };
    }

    return {
        role: 'tool' as const,
        toolCallId: call.id,
        content: runWeatherTool(
            call.validation.value as z.output<typeof weatherParameters>
        ),
    };
});

// Get final response with tool results
const secondResult = await generate({
    model,
    messages: [
        ...initialMessages,
        resultToMessage(firstResult),
        ...toolMessages,
    ],
    tools: { get_weather: weatherTool },
});

console.log('Final response:', secondResult.content);
```

## Tool Choice Strategies

Control when and how tools are used:

```typescript
// Let model decide whether to use tools
const result = await generate({
    model,
    messages,
    tools: { get_weather: weatherTool },
    toolChoice: 'auto', // Default behavior
});

// Force model to use at least one tool
const result = await generate({
    model,
    messages,
    tools: { get_weather: weatherTool },
    toolChoice: 'required',
});

// Disable tool usage
const result = await generate({
    model,
    messages,
    tools: { get_weather: weatherTool },
    toolChoice: 'none',
});

// Force a specific tool
const result = await generate({
    model,
    messages,
    tools: { get_weather: weatherTool },
    toolChoice: { type: 'tool', toolName: 'get_weather' },
});
```

## Multiple Tools

Provide multiple tools for the model to choose from:

```typescript
import { defineTool, generate } from '@core-ai/core-ai';
import { z } from 'zod';

const weatherTool = defineTool({
    name: 'get_weather',
    description: 'Get current weather information',
    parameters: z.object({
        location: z.string(),
    }),
});

const timeTool = defineTool({
    name: 'get_time',
    description: 'Get current time in a timezone',
    parameters: z.object({
        timezone: z.string().describe('IANA timezone name'),
    }),
});

const searchTool = defineTool({
    name: 'search_web',
    description: 'Search the web for information',
    parameters: z.object({
        query: z.string(),
        limit: z.number().default(10),
    }),
});

const result = await generate({
    model,
    messages: [
        {
            role: 'user',
            content: 'What is the weather in London and what time is it there?',
        },
    ],
    tools: {
        get_weather: weatherTool,
        get_time: timeTool,
        search_web: searchTool,
    },
    toolChoice: 'auto',
});

// Model may call multiple tools
if (result.finishReason === 'tool-calls') {
    console.log('Tools called:', result.toolCalls.length);
    result.toolCalls.forEach((call) => {
        console.log(`- ${call.name}:`, call.arguments);
    });
}
```

## Validate tool calls

Tool arguments come from the model, so validate them before you execute
anything, whether the tool is strict or not. How you validate depends on the
tool's `parameters`:

- **Standard Schema**: core-ai validates each call against the schema and
  stores the outcome in `ToolCall.validation`. It is `{ value }`, holding the
  schema's output, or `{ issues }`, listing each problem with a `message` and
  an optional `path`. An invalid call is reported, never thrown. So is a
  validator that throws, such as a transform calling `new URL()`: its error
  message becomes the only issue.
- **Plain JSON Schema**: core-ai sends the schema as is and does not validate
  calls. Validate `ToolCall.arguments` yourself.

`validation` is set on `GenerateResult.toolCalls`, on the matching `tool-call`
parts, and on the `toolCall` of each `tool-call-end` stream event. A call to a
tool that is not in `tools` has no `validation`. `ToolCall.arguments` always
holds the arguments exactly as the model sent them.

`validation.value` is typed `unknown`, because a result can contain calls to
any of your tools. After checking `call.name`, narrow it to that tool's output
type, such as `z.output<typeof weatherParameters>`. See
[Handling tool calls](#handling-tool-calls) for a complete loop.

`validation.value` can hold values that are not plain JSON, such as a `Date`
produced by a transform, so it stays out of conversation history:
[`resultToMessage()`](/api/core/utilities#resulttomessage) omits it, adapters
never send it, and you should not persist it.

### JSON Schema tools

Use plain JSON Schema for tools whose schemas you receive at runtime, such as
tools listed by an MCP server:

```typescript
import { defineTool, type JsonSchema, type ToolSet } from '@core-ai/core-ai';

type McpTool = {
    name: string;
    description?: string;
    inputSchema: JsonSchema;
};

function toToolSet(mcpTools: McpTool[]): ToolSet {
    return Object.fromEntries(
        mcpTools.map((tool) => [
            tool.name,
            defineTool({
                name: tool.name,
                description: tool.description ?? '',
                parameters: tool.inputSchema,
            }),
        ])
    );
}
```

Calls to these tools carry no `validation`. Validate their `arguments` with a
JSON Schema validator, or let the MCP server reject invalid input. To have
core-ai validate them, wrap your validator in the Standard Schema interface:

```typescript
import type { JsonSchema, StandardSchemaWithJson } from '@core-ai/core-ai';

function withValidator(
    jsonSchema: JsonSchema,
    // Returns one message per problem, or none when the value is valid
    check: (value: unknown) => string[]
): StandardSchemaWithJson {
    return {
        '~standard': {
            version: 1,
            vendor: 'my-app',
            validate: (value) => {
                const messages = check(value);
                return messages.length === 0
                    ? { value }
                    : { issues: messages.map((message) => ({ message })) };
            },
            jsonSchema: {
                input: () => jsonSchema,
                output: () => jsonSchema,
            },
        },
    };
}
```

## Handling Tool Calls

Execute validated tool calls the same way for strict and non-strict tools.
Send validation issues back as an error tool result so the model can correct
its call:

```typescript
import { defineTool, generate, resultToMessage } from '@core-ai/core-ai';
import { z } from 'zod';

const weatherParameters = z.object({
    location: z.string(),
    unit: z.enum(['celsius', 'fahrenheit']).default('celsius'),
});

const weatherTool = defineTool({
    name: 'get_weather',
    description: 'Get weather information',
    parameters: weatherParameters,
});

type WeatherArgs = z.output<typeof weatherParameters>;

function getWeather(args: WeatherArgs): string {
    // Implement your weather API call here
    return JSON.stringify({ temperature: 20, condition: 'sunny' });
}

const result = await generate({
    model,
    messages: [{ role: 'user', content: 'Weather in Paris?' }],
    tools: { get_weather: weatherTool },
});

if (result.finishReason === 'tool-calls') {
    const toolMessages = result.toolCalls.map((call) => {
        // Calls to unknown tools have no validation
        if (call.name !== 'get_weather' || !call.validation) {
            return {
                role: 'tool' as const,
                toolCallId: call.id,
                content: JSON.stringify({
                    error: `Unknown tool: ${call.name}`,
                }),
                isError: true,
            };
        }

        // Report invalid arguments back to the model
        if (call.validation.issues) {
            return {
                role: 'tool' as const,
                toolCallId: call.id,
                content: JSON.stringify({
                    error: 'Invalid arguments',
                    issues: call.validation.issues,
                }),
                isError: true,
            };
        }

        // Execute tool with the schema's output; the default unit is applied
        try {
            const result = getWeather(call.validation.value as WeatherArgs);
            return {
                role: 'tool' as const,
                toolCallId: call.id,
                content: result,
            };
        } catch (error) {
            return {
                role: 'tool' as const,
                toolCallId: call.id,
                content: JSON.stringify({ error: String(error) }),
                isError: true,
            };
        }
    });

    // Continue conversation with tool results
    const finalResult = await generate({
        model,
        messages: [
            { role: 'user', content: 'Weather in Paris?' },
            resultToMessage(result),
            ...toolMessages,
        ],
        tools: { get_weather: weatherTool },
    });

    console.log(finalResult.content);
}
```

## Tool Calling with Streaming

Handle tool calls during streaming:

```typescript
import { stream, defineTool } from '@core-ai/core-ai';
import type { ToolCall } from '@core-ai/core-ai';
import { z } from 'zod';

const calculatorTool = defineTool({
    name: 'calculate',
    description: 'Perform a calculation',
    parameters: z.object({
        expression: z.string().describe('Mathematical expression'),
    }),
});

const result = await stream({
    model,
    messages: [{ role: 'user', content: 'What is 25 * 17?' }],
    tools: { calculate: calculatorTool },
});

const toolCalls: ToolCall[] = [];

for await (const event of result) {
    switch (event.type) {
        case 'text-delta':
            process.stdout.write(event.text);
            break;

        case 'tool-call-start':
            console.log(`\nCalling tool: ${event.toolName}`);
            break;

        case 'tool-call-delta':
            // Tool arguments are being streamed
            process.stdout.write(event.argumentsDelta);
            break;

        case 'tool-call-end':
            // event.toolCall carries the validation outcome
            console.log(`\nTool call complete:`, event.toolCall.validation);
            toolCalls.push(event.toolCall);
            break;
    }
}

const response = await result.result;

if (response.finishReason === 'tool-calls') {
    console.log('Need to execute tools:', toolCalls);
}
```

## Tool Result Messages

Structure tool results properly:

```typescript
import type { ToolResultMessage } from '@core-ai/core-ai';

// Success case
const successMessage: ToolResultMessage = {
    role: 'tool',
    toolCallId: call.id,
    content: JSON.stringify({
        result: 'success',
        data: {
            /* ... */
        },
    }),
};

// Error case
const errorMessage: ToolResultMessage = {
    role: 'tool',
    toolCallId: call.id,
    content: JSON.stringify({ error: 'Something went wrong' }),
    isError: true, // Mark as error
};
```

## Helper: Convert Result to Message

Use `resultToMessage()` to simplify conversation building:

```typescript
import { generate, resultToMessage } from '@core-ai/core-ai';

const messages = [{ role: 'user', content: 'What is the weather?' }];

const firstResult = await generate({
    model,
    messages,
    tools: { get_weather: weatherTool },
});

// Convert result to assistant message automatically (drops `validation`)
const assistantMessage = resultToMessage(firstResult);

messages.push(assistantMessage);

// Add tool results
if (firstResult.finishReason === 'tool-calls') {
    const toolResults = executeTools(firstResult.toolCalls);
    messages.push(...toolResults);

    const secondResult = await generate({ model, messages, tools });
    console.log(secondResult.content);
}
```

## Best Practices

<AccordionGroup>
  <Accordion title="Validate tool arguments before execution">
    Check `call.validation` for Standard Schema tools, and validate `call.arguments` yourself for plain JSON Schema tools:

    ```typescript
    const { validation } = call;

    if (validation === undefined) {
      // Plain JSON Schema tool: validate call.arguments yourself
    } else if (validation.issues) {
      return {
        role: 'tool',
        toolCallId: call.id,
        content: JSON.stringify({ issues: validation.issues }),
        isError: true,
      };
    } else {
      // Use the schema's output, not the raw arguments
      const result = executeTool(validation.value);
    }
    ```

  </Accordion>

  <Accordion title="Add detailed tool descriptions">
    Help the model understand when to use tools:

    ```typescript
    const tool = defineTool({
      name: 'get_weather',
      description: 'Get current weather information for a specific location. Use this when users ask about weather, temperature, or conditions.',
      parameters: z.object({
        location: z.string().describe('City name or location. Examples: "London", "New York, NY", "Tokyo, Japan"'),
      }),
    });
    ```

  </Accordion>

  <Accordion title="Handle errors gracefully">
    Return errors as tool results instead of throwing:

    ```typescript
    try {
      const result = await executeToolFunction(args);
      return {
        role: 'tool',
        toolCallId: call.id,
        content: JSON.stringify(result),
      };
    } catch (error) {
      return {
        role: 'tool',
        toolCallId: call.id,
        content: JSON.stringify({
          error: error.message,
          type: error.name,
        }),
        isError: true,
      };
    }
    ```

  </Accordion>

  <Accordion title="Limit tool execution time">
    Prevent tools from hanging:

    ```typescript
    async function executeToolWithTimeout(
      tool: () => Promise<string>,
      timeoutMs: number = 5000
    ): Promise<string> {
      const timeoutPromise = new Promise<never>((_, reject) =>
        setTimeout(() => reject(new Error('Tool timeout')), timeoutMs)
      );

      return Promise.race([tool(), timeoutPromise]);
    }
    ```

  </Accordion>
</AccordionGroup>
